# 首页统一计时页

## 已明确的需求

- 首页只保留计时和预设；点击、滑动、长按排序及按栏目ID恢复继续可用。
- 计时页共用当前模式、四档、自定义时长和提醒配置：开始按钮仅计时，App图标直接计时并打开App。正计时也支持App启动。
- 预设仍使用保存配置；现有默认值、自定义记忆、权限、节点校验、回退、防重复及C4限制保留。
- App区保留四列、名称、管理和末尾添加；每日额度管理可达，无嵌套滚动。
- 旧App栏目映射计时，顺序去重；恢复旧App选择进入计时，不改用户计时选择。

## 实现选择（普通UI细节由开发处理）

使用一块连续面板，上部为模式、常用时长/自定义和开始按钮，下部为App网格。轻分隔线表达两种启动方式；去掉“常规计时”重复标题及App配置摘要，只保留一句共同说明。沿用主题、原生Compose和当前组件，不引入依赖。

App管理与启动继续由QuickLaunchCard负责，作为面板的内嵌部分；不复制选择、权限或启动逻辑。选择保留在MainActivity页外，两种入口接收同一个mode/seconds。活跃会话操作仍跨栏目可见。

### 方案取舍

- 采用原组件内嵌同一面板：改动小，配置和启动链路已有，符合本次要求。
- 不采用两张完整卡片叠放：延续原分区割裂和重复摘要。
- 不新建统一启动器/计时编辑器：现有服务与App启动器已做业务校验，额外抽象不解决本次问题。

### 顺序与恢复

有效旧三栏排列先apps→timer，保留第一次出现的位置并去重；新两栏顺序直接读取。畸形/缺项回退默认timer,presets，不丢失入口。存储归一为两个ID。旧恢复ID apps解析为timer；页外模式/时长不参与导航迁移。旧App页滚动对应旧内容，不强行套用到新增的合并页面；计时及预设现有滚动按ID保留。

## 范围与验收

不改计时、预设、额度、C4、桌面入口或权限。验证迁移六排列、恢复ID、两栏排序/滑动/滚动、两模式两入口、权限/节点/失败、防重复和活跃会话恢复；检查深浅主题/大字/小屏并展示实际页面。按现有检查入口交付，保持版本、不合并/发版。
