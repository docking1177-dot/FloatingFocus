# 正计时周期提醒与长时长显示

用户已选择：随预设保存；按推荐直接实施，无需再逐步确认。基线为本地411c246（公开同应用树09bce45），开发分支codex/stopwatch-reminders。

## 明确需求

- 初/中/高级是三条独立周期规则，各自开关、间隔和效果；不是倒计时百分比节点。5/15/30分钟各自重复。
- 复用服务、累计数据、现有效果与分秒滚轮；声震由用户明确开启。
- 正计时不足一小时MM:SS，达到一小时HH:MM:SS，小时至少两位、不按24小时归零；统一各入口并稳定布局。
- 覆盖暂停/亮屏暂停、同点到达、异常续计、59:59进位、长小时数及旋转；提供实际证据和真机边界。

## 已选方案及理由

新增纯周期计算器，现有FloatingService为唯一时钟/会话/调度宿主，共用现有视觉/音频/震动实现。超时引擎有随机间隔和归零阶段语义，不能直接套用；新服务/平行计时不符合轻量边界。

规则随当前配置/预设快照保存，开始后固定；普通/快捷App/磁贴/组件的默认开始读取当前规则，首页/桌面/组件预设均读保存规则。编辑草稿取消不写。续计读取原检查点规则与承接累计，不读取后来全局规则，也不重新执行预设。旧预设/检查点缺字段默认三级关闭，不推测旧选择；新坏字段按现有严格读取策略报错。

另一方案是与超时提醒相同的即时全局规则，改动较小，但会使保存预设及活跃会话随设置改变；用户已选择快照方案。声音/震动的本功能总许可独立全局、默认关闭、即时生效，不入预设；保存的效果请求不能重新打开已关闭的许可。C4音效和既有归零震动开关含义不改。

## 实施时采用的补充建议与普通细节

- 三级默认关闭；默认间隔5/15/30分钟。复用既有选时默认范围60—10800秒，支持分秒值，不加新范围设置。
- 每级可组合背景提亮、描边、累计状态、两段短震动、短音；默认仅背景提亮。等级仅表示同时到达时的优先级，不自动改变音量/频率；复用标准强度，不增加强度设置。
- 周期依据Countdown累计有效运行时间：手动和屏幕暂停不计；整数倍到达。同一次采样多级到达仅用最高级效果，所有到达规则均推进到自己的下一个未来整数倍，避免叠加/重复/集中补发。
- 续计初始化到承接累计之后的下一个节点，不补过去或截止点事件。延迟回调最多一次，不补队列；本轮不增加唤醒锁或精确闹钟。
- 设置新增“正计时提醒”，共用规则编辑组件嵌入正计时预设草稿。视觉预览复用真实浮窗，读假数据，不创建服务/记录；声震仅明确点击试听且总许可允许，退出停止资源。
- 状态文字使用预留空间，不强制展开、移位或改透明度；结束/暂停/换会话清理效果和回调。重新允许声震不能复活已播放/被过滤的旧提示。

## 长时长实现

现formatElapsed一直输出总分钟；formatUsageTime小时未补零。应用可控的正计时读数统一复用小时格式：00—59分显示MM:SS，1小时起至少两位小时，100小时起自然增长，保持Long整数计算。

浮窗沿用等宽字与既有锚点；正计时预留至少三位小时槽，覆盖59:59/99:59:59进位，较长值按实际安全尺寸测量显示，不裁剪/省略或自动缩字。普通倒计时剩余格式与C4装置不改。

桌面组件仍由系统Chronometer计秒，仅在1小时/10小时格式区间变化时通过现有会话流更新补零格式，不新增逐秒组件轮询。AOSP的Chronometer原生为H:MM:SS；通知无法通过公开Builder指定小时补零格式，因此正计时通知使用现有服务每秒采样刷新可控读数，原通知动作和安静频道保持，不创建新时钟/权限/服务。系统可能限速通知刷新，必须设备验证，不能只用纯格式测试代表桌面/通知通过。
