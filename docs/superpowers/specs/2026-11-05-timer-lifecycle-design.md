# 正计时生命周期、计时方式与方向位置设计

日期：2026-11-05。状态：用户已确认整组推荐方案；按设计实施，不合并、不发版。

## 1. 明确需求与现状

本轮明确要求：划掉最近任务后保留正在运行的计时与浮窗；正计时异常结束后允许明确续计且不补停机时间；设置只选择正计时行为而不开始；修复横转竖数字偏移；两个方向分别记住位置且隔离预设。

已检查的当前代码：

- `FloatingService.onTaskRemoved` 经 `TimerTaskPolicy` 主动以 `TASK_REMOVED` 结束主任务会话。这是原产品规则，不是缺少另一套服务。
- 服务已有 specialUse 前台通知、屏幕广播与公开 DisplayListener，返回 `START_NOT_STICKY`；本轮没有使用情况、无障碍、开机自启或定时拉活需求。
- `ScreenOnTimerScreen` 的开关实际启动/结束一个独立来源的正计时，并未保存行为偏好。
- 新亮屏记录已有可靠活动区间。旧普通正计时记录只保存物理跨度，可能含手动暂停，不能据此还原精确运行累计；`TimerRecord.recover` 目前只把遗留 RUNNING 标成 INTERRUPTED。
- 预设只有一份 `lastPosition`，普通浮窗宿主也只有一份 `rememberedAnchor`。展开临时锚点保存绝对像素，旋转没有清除；折叠布局同样允许时间标题偏离外框中心以追随锚点。

修改前诊断：专用 Android 16/API36 模拟器，源码 `97600d5`，已安装 Debug APK 与本机产物 SHA256 均为 `203256b93b8fc24045f359fe90d084ed760dba9d207b489398b5167c9c706f59`。横屏展开拖至右侧，再回竖屏收起：外框宽410px，标题中心270px，外框中心205px，偏移65px。未拖动的折叠旋转路径标题仍居中，不能笼统称所有旋转都异常。原始坐标/截图在 `.tools/device-diagnostics/20261105-rotation-drag-before/`，已逐文件核对还原应用数据和方向设置。这是修改前诊断，不是修复通过证据。

## 2. 重要决策：推荐与替代

以下为补充设计取舍，2026-11-05 用户已明确确认整组推荐方案；与第1节原始明确需求区分。

| 决策 | 推荐方案与理由 | 替代方案及代价 |
|---|---|---|
| 任务划除影响哪些会话 | 所有已启动的正式计时均继续，包括倒计时、正计时及C4；划除只做检查点，不结束。统一规则，避免来源不同导致退出差异 | 仅亮屏正计时继续，会使其他计时仍被划掉结束，偏离本轮“正在运行的计时”要求 |
| 系统真正终止进程 | 不自动拉活。再次进入FF时提供正计时明确续计；强停及系统“停止应用”必须生效 | sticky重启/开机广播/定时唤起会扩大生命周期与后台机制，且不能保证厂商清理后存活，本轮不采用 |
| 新行为的作用范围 | 当前配置用于普通开始、快捷App、磁贴及组件默认启动；正计时预设保存自己的行为快照，桌面/组件预设按ID读最新预设。倒计时不受影响 | 所有预设跟随全局更省字段，但同一预设会因全局变更而表现不同；仅手动入口支持会使各入口不一致 |
| 默认与生效时机 | 初次为“息屏仍计时”，保持原普通正计时。会话开始快照；修改仅影响下一次。旧预设缺字段按息屏仍计时 | 立即变更活跃会话需处理自动/手动暂停切换，可能突然停止或继续，本轮不采用 |
| 续计与历史关系 | 原中断记录保留，创建关联的续计段。时间显示带上此前可靠累计；新记录、统计和额度仅记录新段。方便审计且不改写旧记录 | 在原记录不断追加跨进程段，需同时重做记录跨度、历史拆分及额度游标迁移，改动更大 |
| 续计是否打开App | 只续计，不主动打开第三方App；保留原App归属及扣额对象。不重新执行预设或使用被编辑后的时长 | 自动重新打开App会增加启动失败、权限与回退语义，超出恢复计数所需 |
| 续计位置归属 | 新检查点保存位置上下文（普通或原预设ID及已知双向锚点）；原预设仍在时继续该ID的位置表。已删除时使用续计会话内的位置副本，不写普通表、不复活预设，避免串位置 | 全部恢复到普通表更省字段，但预设续计的拖动会影响普通计时位置 |
| 新正计时记录口径 | 新建正计时均保存实际运行区间；手动暂停和息屏自动暂停都不算有效累计。旧记录保留原口径不重算 | 继续让新普通记录含暂停跨度，会使续计读数与历史难以核对；若采用此替代需额外提示两种累计 |
| 无可靠字段的旧普通记录 | 保留查看/导出，解释无法可靠续计；不把跨度冒充运行时长。已有亮屏区间的异常记录可续计 | 用旧跨度约计续计可能把暂停算入，需要用户额外接受误差，不作为默认 |
| 两方向位置的持久化 | 普通/快捷App共享一份普通位置表，预设按稳定ID各有位置表；两者均分横/竖持久保存，不互串 | 普通位置只在当前会话内记忆更省存储，但退出后不再满足持续位置记忆的预期 |
| 旧单位置迁移 | 缺少方向信息时，首次启动所处方向承接旧位置；另一方向用安全默认。已有任何独立方向值不得被旧值覆盖；保留旧字段用于兼容核对 | 猜测旧值必为竖屏可能放错；复制到两个方向不符合缺失方向安全默认建议 |

## 3. 生命周期与系统边界

- 最近任务划除：取消 `finishSession(TASK_REMOVED)`，保留既有服务、通知、窗口和屏幕监听；下次进主页读取同一活跃会话。未开始计时不因划除创建任何东西。
- 一键清理：若系统仅移除任务，继续；若厂商同时结束进程，无法保证。可在现有计时方式页提供简短系统限制说明，必要时给出应用信息入口，由用户自行选择厂商后台设置。不申请电池豁免、不自动调整设备设置。
- 系统回收、崩溃、重启或强停：不承诺最后一刻回调；只认已原子保存的检查点。停机不计，亮屏事件不能在进程死亡后重启服务。
- 用户在浮窗、通知、主页或组件明确结束：正常结束，不出现待恢复。C4归零前/归零后的原结束权限不变；本轮不新增C4退出旁路。
- Android“活动应用→停止”和应用信息“强行停止”必须真正停止；重新启动FF也不能自行继续。系统来源若无法精确分辨，只展示“上次中断、约计”，不猜测是用户清理还是崩溃。

官方依据：[Service.onTaskRemoved](https://developer.android.com/reference/android/app/Service#onTaskRemoved(android.content.Intent))、[stopWithTask默认false](https://developer.android.com/guide/topics/manifest/service-element#stop)、[Android 13起系统停止前台服务应用](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)。最后一项会停止整个应用且没有结束回调，不能靠onDestroy保证精确结算。

## 4. 正计时方式与入口

复用现有设置条目改名为“正计时方式”，内容为两项单选，不保留立即开始的开关：

- **息屏仍计时**：亮屏、息屏持续累计；可通过现有入口手动暂停/继续和结束。
- **随亮屏计时**：正常亮屏累计（含未解锁），息屏/AOD暂停；仅屏幕事件暂停/继续，手动入口查看/结束。

设置页只持久化偏好，不请求悬浮权限，不启动服务或声音。必要说明：“仅影响下次开始的正计时；预设使用保存的方式。”预设编辑复用同一选择组件、独立草稿，取消不写任何配置；保存当前时采样当前偏好。独立正计时有效C4始终关闭，不改变全局C4值。

共用启动流程解析一次行为，私有请求传入服务，服务再次校验。普通开始、快捷App、桌面预设、组件和磁贴不各自实现判定。绑定App的随亮屏正计时保留绑定并仅在运行时扣额度，手动未绑定会话不扣任何App；不进行App前台检测。

## 5. 正计时异常恢复

### 入口与展示

- 主页空闲时提供最新一条可续计任务的紧凑入口；记录页在对应异常记录中提供“继续计时”，其他候选从记录页访问。不弹强制恢复对话框。
- 展示App/手动计时、已保存累计、计时方式、最后保存时间及“停机不计、可能少记最后未保存进度”。已经续接的祖先记录只显示关联，不再次提供恢复。
- 有活跃会话/启动请求时不可覆盖，说明先结束当前计时。读错时显示重试，不使用空记录/零值继续。

### 记录与启动

- 每次续计新建稳定段ID，保存 `continuationOf`、根ID及此前可靠累计。当前读数为携带累计+新段实际运行值；历史/图表/CSV每段只计自己的区间，携带累计不进入分桶求和。
- 读取最新可恢复记录→检查类型/检查点/后继关系/当前会话→复用启动占用门禁与悬浮权限→启动既有服务→成功后创建关联新段。仅传受控记录ID，不接受外部任意累计或包名执行。
- 重复点击、页面重建、旧请求和并发入口只能接受一次。后继记录的原子持久化是来源已消费的依据；若启动在服务可用前失败，不消费来源或制造有效计时记录。中途再次异常时只续最新未消费中断段。
- 新段使用保存的正计时方式，不重读全局行为；不重启C4，不重新执行预设，不打开App。原App绑定继续用于历史/额度，仍复用当前普通外观应用规则；本轮不创建完整会话外观快照系统。
- 新检查点保存位置上下文：普通计时继续普通双向表；预设来源保留稳定预设ID，存在时读取该ID最新位置并将用户拖动写回同一ID，不重新读取或执行预设的模式/目标App/时长。预设已删除时从检查点中的双向锚点建立会话内副本，只写续计检查点，不写普通位置或任何其他预设。旧亮屏记录没有预设来源，按普通来源处理，不根据App名称猜测预设。
- 额度使用新段的服务身份和新进度游标，仅结算启动后的运行区间；不从历史累计回扣，不补停机或暂停时间，跨日规则保持。
- 普通手动结束及旧版 TASK_REMOVED 不作异常恢复。真正已运行后的 INTERRUPTED/意外 SERVICE_STOPPED/ERROR 可候选；失败启动、取消启动及缺失可靠检查点的旧普通记录不可候选。

### 兼容

沿用 `TimerRecordStore` 每记录AtomicFile及串行I/O，不建立第二套历史库。复用活动区间校验并为新普通正计时增加可靠运行检查点；源类型与关联字段显式区分，不把损坏数据当旧版本。旧CSV列保留，尾部追加恢复来源和累计说明；历史按每段自身时段归属，不重复相加。旧记录不改写。原倒计时/超时统计口径保持。

## 6. 方向位置与旋转布局

- 宿主在一次测量中获取安全区域与横/竖方向，为当前方向选用户锚点。反向横屏共用横屏槽，反向竖屏共用竖屏槽；分屏/导航栏变化仅重新适配安全区域，不把临时clamp保存成拖动。
- 环境变化清除旧像素pin和不再匹配的内容placement，按新方向重新测量内容与定位，再将真实尺寸/位置同次提交WindowManager。不能在布局后反复补移窗口。
- 折叠态时间在自己的可见容器中居中；普通展开仍以该方向实际时间区域为锚点，向下优先、必要时向上，收起恢复该方向位置。旋转后不追逐旧方向的屏幕像素坐标。
- 只在真实用户拖动结束保存相应方向；旋转中取消旧拖动，不将横屏手势尾事件写入竖屏槽。展开、收起、动态倍率和系统边界修正不覆盖记忆。
- 普通位置表与预设位置表使用相同锚点数据结构，后者保留稳定ID；改名/编辑保留，删除仍按原规则删除，不复活预设。首次无记录用各方向安全默认位置。移到当前安全区外仅做最小边界修正。
- C4装置仍复用窗口位置适配，不修改专用形态、内部布局、时间轴或手势优先级。
