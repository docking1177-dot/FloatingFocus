# 双浮窗、透明度分离与横屏边界

用户已确认整组建议并授权直接实施，无需逐步确认。

## 明确需求与已确认行为
- 最多两个独立正式会话，可来自同 App/预设；第三次启动明确拒绝，不覆盖已有会话。
- 首页分别控制；组件与磁贴默认控制最早创建的一路；控制命令绑定会话 ID 和计时段。
- 同 App 额度按重叠运行区间去重；历史仍为两条各自会话，不合并或回写旧记录。
- 同时最多一路 C4，可与普通会话共存；C4 固定外观保持。
- 普通窗背景与数字/图标不透明度独立；旧值迁入两项。普通窗跟随当前配置，预设窗使用启动快照，不临时改全局设置。
- 横屏可拖至实际安全区底边，保留系统导航安全区。

## 实现选择与边界
复用一个 FloatingService，把现有单会话资源封装为服务内会话对象，由宿主管理容量、通知生命周期和状态聚合。不创建第二个服务、并行计时模型、新权限或依赖。
替代方案：复制服务会导致生命周期与启动逻辑分叉；仅复制窗口会共用计时/结束操作，均不采用。
单一公开 session 保留最早活跃会话兼容组件；新增 sessions 提供首页及请求应答。结束一路不销毁另一路及其通知。异常清理逐路结算，停机时间不补算。
数字/图标与背景分别渲染，原生 alpha 取两者最大值并归一化内容 alpha；锁定时沿用系统阈值限制，不改保存值。
两个相同位置的窗口仅在新窗首次显示时临时错开，不写为用户拖动。
