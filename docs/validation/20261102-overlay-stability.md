# 浮窗布局与 C4 暂停专项

本轮不增加版本号、不合并或发布。以1973707及保留的用户工作区为基线；公开同步时排除本机视频工作。

## 用户观察

用户在本轮明确反馈：REDMI K80、Android16，0.3.0开发包，普通超时选择「累计主显」；启用C4时的展开浮窗和普通超时均会每秒整窗突然闪烁向下移动，再瞬间回原位；折叠正常。先前提供HyperOS为3.0.109.0.WOKCNXM.C11。未提供具体APK哈希和执行时刻，版本号不能反推出源码，记录保持身份未核验。

## 定位与修正

- 暂停：旧共享策略只有c4Active/c4Locked，且浮窗专门开放C4阶段前暂停。改为会话开始发布有效c4Enabled，所有控制和服务共同拒绝暂停/继续；阶段前仍可结束。全局设置不覆盖活跃快照，正计时有效C4仍关闭。
- 测量：旧原生窗口长期WRAP_CONTENT，逐秒文本刷新仍进入ViewRoot测量。现统一按安全显示范围AT_MOST测量，实际像素宽高与位置同次提交，尺寸/位置未变则不更新WindowManager；不以旧窗口的EXACT尺寸限制下一次展开。参考[AndroidX Popup](https://raw.githubusercontent.com/androidx/androidx/androidx-main/compose/ui/ui/src/androidMain/kotlin/androidx/compose/ui/window/AndroidPopup.android.kt)测量路径。此修正仍需Redmi验证，不能据此宣称厂商闪动根因已完全证实。
- 小时进位：`.tools/device-checks/20261102-202908/overlay-stability-samples.json`及连续视频实际捕获普通超时从分钟转小时后，原生宽度449px变464px并横移。OvertimeDigits在同字号/等宽字体下预留小时与前缀宽度，不改累计口径、不裁剪、不缩字。该失败也混有前台Lab预览坐标，后续探针以preview-区分并只读取真实浮窗角色。
- 锚点：C4尚未进入专属阶段时继续使用普通时间区域锚定，完整装置仍独立定位。设备专项明确检查原时间区域下半部连续点击、上下边缘和旋转，不只判断展开后变高。
- 文案：删除累计主显可见「本次累计」，保留时长和超时。无障碍仍说明数值含义；共享C4设置组件简短说明从开始不可暂停。

## 验证边界

首次诊断`.tools/device-checks/20261102-200406`的C4前阶段未等待原生窗口就绪，不能作为该项通过；其它时段不能被错误放大成整套真机验收。后续`.tools/device-checks/20261102-202540`已验证三种展开状态连续七秒的窗口帧和内容坐标稳定、时钟继续、无重复窗口定位。上述均为API36专用headless模拟器，无真实听感或厂商效果验收。

新增C4会话测试先在旧策略失败（215项中2项失败），修改后215项通过。最终构建、设备结果和SHA另见同名JSON；脚本38项通过。跨小时专项必须由Debug实际渲染日志确认采样前后跨过3600000ms，不因录屏产生就写通过。

## 真机最小复测

使用本轮最终SHA的Debug，覆盖安装保留数据。音频仅本机Debug，测试闪动可关闭声音；不要求新权限。系统悬浮权限应已开启。

1. 关闭当前C4，开发者模式选择累计主显，启动2秒倒计时；超时展开观察10秒，在上下边缘点击原时间区两次。期望只更新读数，无整窗闪下回弹，第二次点击收起而非结束。
2. 开启当前C4，普通60秒倒计时。最初15秒展开/收起，确认无暂停且仍可结束；重新开始后进入末段，展开完整装置观察10秒，拖动并收起再展开，输入7355608结束。期望无每秒整窗位移，时钟/输入连续，原规则不变。

两项均尚待用户真机复测。出现异常反馈用例ID、发生时剩余/超时时间、形状、系统版本及是否整窗或内部内容移动，附短录屏即可；ADB连接可用时由AI读取日志，不要求用户手工整理。不能把没有本机音频的Release无声判为故障。
