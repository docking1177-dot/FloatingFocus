# 计时预设

在首页选择时长、在设置页调整外观后，点击「预设方案 → 保存当前」，输入名称并从 FF 已添加的快捷 App 中选择目标后保存。主界面点击方案即可直接应用配置、开始对应计时并打开绑定 App，不再每次选择应用。创建、编辑及首次补绑定都只读取现有快捷列表，不枚举本机应用目录；快捷列表为空时提示先到首页添加。取消不启动、不应用设置；计时运行期间不可重复启动。

「管理」可查看名称、时长、形状和颜色，重命名、编辑或删除。编辑复用正式设置页及预览，额外显示目标快捷 App、方案名称与分钟输入；修改保存在独立草稿中，点保存才写入方案。返回/取消不会影响原方案或当前正式设置。修改手机的正式设置不会自动改写此前保存的方案。

## 复用与数据边界

每个预设按稳定 ID 记忆最后拖放的浮窗中心位置，拖动结束即保存，正常结束后及 App 重启后再次点击该预设会恢复。位置以安全显示区域的比例存于原 `timer_presets/items` 的 `positionX/Y`，横竖屏与尺寸变化时适配并防越界；展开、收起、动态变尺寸及加时的临时避让不覆盖位置。未拖动/旧预设缺少位置时沿用默认右上位置。重命名、编辑保留位置，删除方案同时删除位置；不同预设互不覆盖，同 App 的不同预设也分别记忆。普通手动计时/快捷启动与实验室不写入任何预设位置。无需增加权限。

- `TimerPreset` 保存稳定 ID、名称（1—40 字符）、兼容分钟数（1—180）及精确秒数（1—10800）、计时模式、绑定 App 的包名与显示名和整个 `ReminderSettings` 快照。参数范围、默认值和兼容解码沿用 `ReminderSettingsCodec`。
- `TimerPresetStore` 使用本地 SharedPreferences 的 `timer_presets/items` JSON 数组及进程内 StateFlow；无账号、网络、云同步。记录按 ID 更新，损坏的单条记录跳过，重复 ID 保留首条；整个 JSON 损坏时安全返回空列表。
- `AppTimerLauncher` 从原快捷启动流程提取，常用 App 与方案共用。正式 `FloatingService`、悬浮权限、计时数据和提醒全部复用，添加快捷 App 时仍使用 `launchableApps()`；预设选择仅使用 `quick_launch` 中的列表，不读取使用情况、不启用自动监测或无障碍服务。
- 点击已绑定的方案后才应用方案外观；启动成功后这组外观成为正式设置，之后手动计时可继续使用。若 App 已卸载、服务启动失败、等待超时或页面离开导致取消，关闭本次新建计时，恢复启动前的外观；不会取消既有计时，也不会覆盖等待过程中另行修改的设置。
- 预设编辑不改变正在运行的计时。删除方案不删除 App、不修改外观或计时状态。

## 验收

JVM 测试覆盖完整配置往返、字段校验、旧形状兼容、按 ID 编辑和同名方案区分。设备回归覆盖新建、重启保留、改名、编辑保存/取消、删除取消/确认、选 App 取消与成功启动，以及现有常用 App 快捷启动。

2026-10-23—24 后续验收：Debug 56 项、Release 50 项 JVM 测试通过，最终 Debug/Release 构建及 Lint 通过（Debug 保留 1 项既有 Gradle 更新警告）。Android 16 后台模拟器实际完成预设管理与启动流程、三种形状跨应用拖动/展开/收起/关闭、连续变尺寸和大字体截图检查。详见 [本轮验收记录](validation/presets/results.json)。截图和原始操作文件保存在本机 `.tools/presets-validation/`；这不代表新改动已通过真机验收。

预设现在保存倒计时/正计时模式，旧记录缺少模式字段时默认倒计时；正计时的分钟字段只为兼容与切回倒计时保留，不设截止时间。会话记录及导出见 [TIME_RECORDS.md](TIME_RECORDS.md)。

旧预设缺少目标字段时仍完整保留；点击后补选快捷 App 并保存，之后点击即可一键启动。绑定的 App 被移出快捷列表时需要重新选择；仍在列表但已卸载/停用时复用现有启动错误处理，不产生有效计时记录。修改绑定目标只影响该预设，不修改快捷列表。

## 双列浏览与快捷启动搭配

预设以双列描边卡片纵向排列，整张卡片可一键启动，显示名称（最多两行）、App 与时长／正计时。奇数末项保持单列宽度；沿用首页滚动，不增加嵌套滚动。名称省略时完整名称仍保留在无障碍语义和管理入口中。

预设读取保存的完整配置；快捷启动使用首页当前时长和正式设置。本轮保持两个分区，用描边预设卡片与原有填充快捷按钮区分，未改变 Debug 的快捷布局选择或 Release 固定列表。未来若数量增加，可选择分段切换「预设／快捷 App」共用展示区域，或以预设为主、将常用 App 精简为少量入口并提供展开；这些是可选方案，本轮未实现。
