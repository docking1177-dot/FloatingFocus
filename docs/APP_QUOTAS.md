# 今日 App 额度

## 使用

1. 首页 App → 管理，在已加入的 App 旁点击“每日额度”，设置并保存。未加入的 App 先保存到快捷列表。
2. 管理页顶部设置统一的“每日额度重置时间”，默认 00:00；下方显示固定记账时区。
   计时中仍可查看和编辑额度，App 列表选择/保存保持禁用；不会解锁启动、结束或 C4 限制。
3. 新建/编辑倒计时预设，计时来源选择“今日 App 剩余额度”。首页显示当日余额；点击预设、桌面快捷方式或组件预设按钮都会读取最新余额。固定时长预设保持原行为。

额度总量沿用倒计时已有范围：1 秒至 180 分钟。额度编辑复用分秒滚轮；重置时刻使用原生时钟选择，不混用时长输入。

## 已确认口径

- 按包名共用额度。所有明确绑定 App 的 FF 倒计时、正计时和超时会话都扣；暂停不扣。只有额度来源的倒计时预设把余额作为启动时长。
- 目标 App 成功打开后才开始；直接打开其他 App、未绑定的手动计时、进程停机时间不补扣。不检测 App 前台状态，不新增权限、监测、后台保活。
- 首次启用从当时开始，不导入旧历史。删除/改名/改绑预设、移除快捷 App 不清空账目。停用后保留当日已用，再启用从当时继续。
- 修改总额度保留已用，余额最低零，额外使用单列。耗尽后现有会话照常超时，下次额度来源启动被阻止；固定时长或正计时不被强制结束。
- 额度、来源及日界线编辑不改变正在运行的倒计时、会话或 C4 快照；C4 限制继续有效。

## 统计日与时间变化

账本建立时保存设备时区，以后使用该固定区。设备时区变化不重新赠额，界面显示实际记账区。自然日按该区日历计算，支持夏令时 23/25 小时日。

日界线从下一周期生效；下一次重置安排在**不早于已安排边界**的新时刻，可能延长当前周期。反复编辑或取消待生效时刻也不能提前返额。运行会话按边界拆分消耗，当前倒计时不跳变，下次启动使用新统计日余额。

同一开机期间以单调时钟推进记账时间，明显改动系统时间只提示核对，不跟着日期反复补满。重启后保留时间高水位，不回开过去的日期；纯本地离线无法可靠鉴别所有跨重启人为改时，不作防篡改或真实 App 限制承诺。

## 存储与迁移

- `DailyAppQuota.kt` 是纯模型；`QuotaLedgerCodec.kt` 验证结构并管理失败重试；`AppQuotaStore.kt` 串行 IO + `AtomicFile(files/app_quotas.json)` 保存配置、日期区间、消耗及会话水位。无第二个计时器。
- 同一会话 ID 的 tick、暂停、结束仅结算新运行区间；旧会话/旧请求不扣后来的会话。新进程拥有新记账 owner，不推算老进程离线时间。
- 使用时长写失败保留本进程待写水位重试；失败的配置草稿回滚。读取失败/已初始化但丢失文件会显示错误并阻止绑定 App 启动，不能按空账/满额执行。未绑定手动计时仍可使用。
- 异常结束只保证最后持久化进度；划除 FF 按已有服务生命周期结算停止。原 `timer_records`、CSV、统计图表不修改、不重复累加。
- 预设新增 `timeSource=FIXED/APP_DAILY_QUOTA`，缺字段为 FIXED；非法来源或“正计时 + 额度来源”拒绝读取。保留原 ID、App、时长、模式、外观、C4 与位置。额度预设不保存剩余快照。
- `PresetLauncher` → `AppTimerLauncher` 在互斥启动门内读取额度，用实际剩余毫秒数检查提醒节点；桌面及组件继续只传稳定预设 ID。
