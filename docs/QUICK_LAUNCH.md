# 一键打开目标 App + 手动计时

在主界面选好时长，在「打开 App，开始专注」中选择目标（支持名称/包名搜索），再点击「打开某 App 并计时」。目标选择保存在本机，后续可以直接一键启动或更换。只列出当前用户可启动的 App，排除自身和桌面。

该操作启动普通手动计时。离开目标、Home、锁屏仍继续累计，渐进变色、呼吸提醒和到期确认沿用现有实现。只需原有悬浮权限，不申请使用情况访问，不观察目标的前后台变化。

## 实现与失败处理

- `QuickLaunchCard.kt`：选择与本地记忆、单次启动流程；`LaunchableApps.kt` 复用原有 App 查询逻辑，不添加新依赖或读取全部应用权限。
- 用户在可见主界面点击，先验证目标可启动，再启动原有 `FloatingService`。服务成功进入前台并添加 `OverlayWindow` 后才发布会话成功状态，Activity 随后打开目标。
- 没有悬浮权限时显示原有授权说明，返回后需重新点击。不存在后台自动启动路径。
- 目标卸载/停用、系统拒绝启动、计时器失败或超时（5 秒）会显示说明；仅取消本次操作启动的计时，已有会话不会被替换。
- 等待启动期间离开页面或旋转导致页面重建时取消尚未完成的操作，避免稍后突然打开目标；已成功打开目标后计时由服务继续。
- Android 接受启动请求后，目标自身崩溃或其登录/欢迎页流程由目标 App 处理；本应用不监测这些状态。

App 自动触发计时独立标记为 [Deferred](AUTO_TRIGGER.md)，其源代码与测试保留。

- 统一入口 `scripts/check.ps1 -Mode Emulator -Offline`：Debug 构建、既有 37 项 JVM 测试、安装启动通过，Lint 0 错误、1 项现有 AGP 版本提示。另完成 Release 构建、31 项 JVM 测试和 Lint（无问题）。本轮新增交互以模拟器回归验证，没有新增 JVM 测试。
- Debug/Release 合并 Manifest 均不含使用情况访问、无障碍或读取全部安装包权限。
- API 36 AOSP 模拟器选择 Gallery、设置 1 分钟，一键打开后目标进入前台且有真实浮窗。Home 仍计时、返回目标不重置；观察到 `00:28` 暖色过渡、`00:05` 红色阶段及到期提示，点击浮窗「知道了」清理窗口。
- 使用情况访问保持未授权，Logcat 未出现 `AutoTrigger` 监测日志。向已有手动会话发送旧 `MONITOR` 请求不会重置/中断计时；空闲时发送该请求后服务列表仍为空。
- 目标停用后显示不可打开提示，服务列表为空；未允许悬浮窗时显示授权说明，没有新计时、没有打开目标。测试后恢复模拟器原权限与目标 App 状态。
- 进程关闭重开后保留 Gallery 选择；普通「开始倒计时」独立运行，快捷启动按钮禁用。拖动位移、展开、收起与手动结束通过。未发现本应用崩溃日志。
