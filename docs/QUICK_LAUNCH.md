# 一键打开目标 App + 手动计时

在主界面选好时长，在「打开 App 并计时」分组点「添加/管理」（支持名称/包名搜索），勾选多个目标并保存，再点击任意目标打开并计时。目标列表保存在本机，可随时取消勾选移除；取消管理弹窗不会改变已保存的列表。旧版本的单个目标自动保留为第一项。多个目标是多个快捷入口，每次仍只启动一轮计时。

列表、双列网格与横向栏均显示本机 App 图标及名称，保留完整的无障碍操作标签，共同启动说明只出现在分组层级。图标异步读取，无新增权限或第三方图片库；不可用包显示通用占位并保留原启动错误提示。Debug 布局比较默认收起。首页操作与说明分区，「使用与提醒说明」默认折叠；缺失悬浮权限时在开始按钮附近显示授权提示，授权返回后隐藏。

只列出当前用户可启动的 App，排除自身和桌面；已保存但卸载/停用的目标会在管理页显示「不可用」，可移除。点击不可用目标时仍保留原有失败提示。

## 三种布局

| 方案 | 适合情况 | 取舍 |
| --- | --- | --- |
| 列表 | 少量常用 App、较长名称 | 点按清楚；目标多时占用纵向空间 |
| 双列网格 | 多个常用 App | 同屏数量更多；长名称最多显示两行 |
| 横向快捷栏 | 希望主界面紧凑 | 左右滑动查看更多，部分目标不在首屏 |

Debug 在快捷区提供三种布局切换，选择保存在独立调试偏好中；三种布局共用目标列表、时长与启动逻辑。Release 固定使用列表，不包含布局选择控件。可先用 Debug 比较后再决定正式布局。

该操作启动普通手动计时。离开目标、Home、锁屏仍继续累计，渐进变色、呼吸提醒和到期确认沿用现有实现。只需原有悬浮权限，不申请使用情况访问，不观察目标的前后台变化。

## 实现与失败处理

- `QuickLaunchCard.kt`：多选管理、列表持久化和三种布局、单次启动流程；`QuickLaunchTargets.kt`：旧选择迁移、去重和稳定顺序；`LaunchableApps.kt` 复用原有 App 查询逻辑，不添加新依赖或读取全部应用权限。JSON 使用 Android 自带实现。
- 用户在可见主界面点击，先验证目标可启动，再启动原有 `FloatingService`。服务成功进入前台并添加 `OverlayWindow` 后才发布会话成功状态，Activity 随后打开目标。
- 没有悬浮权限时显示原有授权说明，返回后需重新点击。不存在后台自动启动路径。
- 目标卸载/停用、系统拒绝启动、计时器失败或超时（5 秒）会显示说明；仅取消本次操作启动的计时，已有会话不会被替换。
- 等待启动期间离开页面或旋转导致页面重建时取消尚未完成的操作，避免稍后突然打开目标；已成功打开目标后计时由服务继续。
- Android 接受启动请求后，目标自身崩溃或其登录/欢迎页流程由目标 App 处理；本应用不监测这些状态。

App 自动触发计时独立标记为 [Deferred](AUTO_TRIGGER.md)，其源代码与测试保留。
