# 正式设置与到期提醒

## 跟随系统深浅模式

`FocusTheme` 默认使用系统夜间标志，首页、设置、历史、教程、快捷方式提示与开发者页面共享语义色；不新增独立开关或持久化偏好。保留原暖白/绿色风格，深色使用深绿灰背景和浅绿强调色，完整提供表面容器、分隔线、辅助文字、错误和逆色角色，避免 Material 默认紫色混入。

平台窗口与原生控件通过 `values-night/styles.xml` 匹配；不依赖强制深色反转。设置与历史页共享24dp页边距及8/12/16dp间距，禁用按钮沿用Material状态，自定义时长整行禁用且文字降强调。系统切换不重置当前设置草稿或计时会话。图表和提示仍使用同一套颜色角色；悬浮倒计时的用户配色、整体透明度以及固定C4配色独立于页面主题。

检查入口为 `test-device.ps1 -Suite theme`：实际切换系统夜间模式，采集主页、设置、原生滚轮、对话框、历史图表/读取错误、禁用态和大字体截图；保存并恢复测试数据及系统显示设置。JVM对比度测试覆盖正文、辅助文案、按钮/容器、错误和图表，不以颜色数值代替设备视觉检查。

首页右上角齿轮进入列表式「设置」，点击「悬浮窗」条目进入参数页。保留原主题与实时预览；返回键从参数页回到设置列表，再返回首页。预设编辑仍直接进入独立草稿，不增加这一步。参数修改自动保存，并即时更新正在运行的正式浮窗；不重启或重置倒计时。

列表另有「提醒」。提醒页集中提供「提醒策略」入口及默认关闭的 C4 末段特效；C4启用状态保存于预设；本页控制普通计时和快捷App的当前配置，音效仍为全局即时控制，见 [C4_COUNTDOWN.md](C4_COUNTDOWN.md)。

常用时长仅从首页「常规计时 → 手动设置」进入，复用现有编辑页，保存、页面返回和系统返回都直接回首页；设置列表不再提供重复入口。仍保存四个不同的时长，范围为 1—180 分钟，支持秒数；默认 5/10/15/30 分钟，按用户顺序显示。保存后即时共享、重启保留，不改变当前选中时长或运行中的会话。

## 统一分秒选时

常用时长页的「启动默认配置」与四个档位独立：默认计时模式可选正/倒计时，默认倒计时为1—10800秒，复用分秒滚轮。首次为倒计时15分钟；正计时隐藏时长入口但保留其值，切回倒计时恢复。四档与启动配置共用原 `quick_durations` 偏好文件，新增 `startup_mode` / `startup_seconds`，保存时一起写入；返回取消草稿，「恢复默认」仅恢复原四档。

采用“仅初始化无恢复状态的新首页”的建议：配置不必匹配四档，非档位时显示紧凑的已选时长；返回前台/旋转保留当前选择，活跃会话使用真实模式和本段总时长，不用剩余时间作新默认。保存默认配置不重置已打开首页，也不自动开始。替代的“每次回前台重选默认”会覆盖刚调整的选择，本轮不采用。自定义时长仍独立记住本页最近值，首次1分钟；快捷App继续使用当前首页选择，预设/外观/记录不改写。

`DurationPicker.kt` 复用 Android 原生 NumberPicker，通过 Compose AndroidView 嵌入；分钟与秒数可独立滑动，中央为当前值。首页「自定义时长」整行可点并带 >；常用时长、预设编辑、浮窗加时和实验室复用同一组件。弹出后回显、确认才应用，取消不修改原值。普通计时与预设为 1—10800 秒，常用与加时仍为 60—10800 秒；提醒节点为 1—10800 秒；实验室总时长 1—10800 秒、剩余/超时量 0—10800 秒，超时正负由独立状态切换，模拟进度仍保留。

秒轮通常为 00—59；在上下限所在分钟限制不可用的秒值，例如 180 分钟仅能选 00 秒。不放宽原业务边界。`quick_durations.seconds` 优先读取，缺失时兼容旧 `minutes`；预设增加 `durationSeconds`，缺失时读取旧 `minutes × 60`。重命名、位置保存不会丢秒数；启动链路直接传毫秒，不向整分钟取整。

## 提醒策略

取消全局三模式入口，统一为 0%—100% 进度轴与第二/三级两个节点标签。拖动按所选类型分别量化为整数百分比或整数秒；点击标签进入条件详情。两个级别各选一种触发类型，因此可以自然混合。标签上下错位，避免接近时遮挡。使用独立草稿，保存生效，返回取消。

剩余时间节点位置 = 1 − 剩余秒数 / 本次总秒数。设置页从首页接收当前时长，编辑预设使用预设草稿时长；时长变化不改用户节点值。开始前由同一 `validationError` 校验真实时长：剩余量不可超过总量，第二级触发时刻必须严格早于第三级，相等也视为冲突。首页、快捷 App、预设在启动前阻止冲突并弹出原因/修改入口；服务再次防御校验。冲突配置不会启动目标 App，不会交换节点或自动改变值。无有效顺序的旧配置显示错误与逐节点修复入口，不能保存。旧全局进度/剩余模式按原义读取；旧混合的双开/全关节点要求明确选一种，不静默迁移为某一种。

默认 50%/80% 不变。`ReminderStrategy` 仍把节点映射到现有效果曲线，颜色、尺寸、闪烁、服务阶段与实验室共用；提醒强度控制幅度。正计时不受倒计时节点限制，归零单次振动及超时逻辑不变。加时用新一段时长重检，冲突时浮窗提示并禁用确认，可调整加时时长解决。

策略复用 `ReminderSettingsCodec` 与预设完整快照。预设的策略只改独立草稿，取消不会写入正式配置。展开/到时面板沿用同一浮窗、缩放及位置锚点；加时默认 2 分钟，使用紧凑分秒滚轮、取消和高对比确认。`OverlayTouchLayout` 尊重滚轮的触摸所有权，滚轮手势不变成窗口拖动，其他区域仍可拖动。

页面上方固定显示实时预览，下方设置独立滚动。预览复用 `ReminderPresenter` 与 `FocusOverlay`，无需悬浮权限；可拖动「预览进度」查看 15 分钟示例的渐变、节点变化和到期外观。初始进度为 0，便于查看基础颜色；后段颜色由所选变色策略决定。预览进度仅用页面的 rememberSaveable 保存，不写入配置或正式会话，不调用服务和震动。预览不支持拖动、展开或结束真实计时。容器随可用高度适配；先测量完整内容，超出预览区域时整体缩小，避免横屏下挤掉时间文字，因此预览不承诺与跨应用浮窗像素等大。

## 配置与效果

- 沿用 `ReminderSettings` 与 `ReminderPresenter`。`ReminderSettingsStore` 使用项目已有的 SharedPreferences 方式，文件名 `reminder_settings`；同进程只有一个 StateFlow 数据源，UI 与服务共同订阅。
- 变色/变尺寸方式默认连续变化，可选节点突变；强度默认 1，范围 0—1；基础大小默认 1，范围 0.75—1.5；不透明度默认 0.94，范围 0.30—1.00。默认效果仍为变色。
- 正式设置的变色、变尺寸为独立开关，可同时开启或全部关闭，分别使用原有变化方式与同一计时进度。关闭只固定相应颜色/尺寸，不关闭既有震动或提亮提醒；强度为 0 才关闭这些提醒。关闭变色使用基础颜色，关闭变尺寸使用基础大小。基础颜色有石墨、蓝、绿、紫、棕五种预设，默认石墨。
- `colorEnabled` / `sizeEnabled` 与正式设置、预设快照一起持久化；旧 `style=COLOR/SIZE` 仅在缺少开关键时迁移为原单一效果，不自动给旧用户开启第二项。交互确认及单独策略对照保留在 Debug 实验室，实验室局部覆盖开关，不写回正式设置。
- 三种形状以并排图形缩略图选择：横向胶囊、纵向胶囊、圆形。旧 `ROUNDED_RECTANGLE` 配置键保留并映射为横向胶囊；圆形键不变，新增 `VERTICAL_CAPSULE`。预览与真正跨应用浮窗共用渲染和几何计算。
- `OverlayGeometry` 按稳定的基础内容测量，再一次性应用提醒大小；不再让 TextView 自动缩字结果反过来决定 WRAP_CONTENT 浮窗尺寸。倒计时数字使用等宽字体；形状、标题及操作按钮随同一比例缩放，屏幕放不下时整体适配。展开、到期时容器可增大以容纳操作。
- 不透明度统一作用于背景、文字和图标，动画期间保持用户配置值。自动提醒与手动动画改为「正常→提亮→正常」：直接将当前形状背景向白色混合，峰值 40% × 提醒强度；不添加矩形图层，不淡出。手动播放两轮，自动提醒沿用紧急阶段和 2400ms 周期，并遵循系统动画开关与屏幕交互状态。
- 橙色阶段为更明亮的琥珀橙 `#C47F00`，红色阶段为饱和红 `#D10B25`，默认 50%／80% 节点，可由提醒策略调整。文字和图标按当前背景亮度选用黑／白，白字保留轻微阴影；实色对比度测试覆盖连续颜色及提亮过程，不能保证透明叠加复杂底图后仍达到同一对比度。低不透明度会同时减弱文字与颜色。
- Android 13+ 使用官方 `AttachedSurfaceControl.setTouchableRegion` 让触摸区域按形状匹配，透明角落可穿透。Android 10—12 的公开 API 不提供此方法：形状外拒绝点击/拖动，但底层系统窗口仍按矩形接收输入，不能保证角落透传。未使用非 SDK 反射或新增权限。
- 原实验参数只存在内存中，没有旧持久化配置需要迁移。旧快捷启动等 SharedPreferences 不变；缺省、损坏或未知配置键按字段恢复默认值/合法范围。实验室不保存一份平行配置，读取正式外观参数、保留自己的实验策略和时间；重置模拟不重置正式设置。

## 震动排查与修正

源码检查确认：原服务归零会调用 `ReminderVibration.once`，Manifest 已声明 VIBRATE，API 29/31 的振动器获取分支存在。没有“后台就跳过”的条件。原正式路径没有传入提醒强度，且只提交 180ms 的 NOTIFICATION 震动，没有调用结果诊断。

2026-10-23 的旧 APK 对照：Android 16 模拟器在 Home 后正常归零，系统记录 `usage=NOTIFICATION`、`finished`、180ms。因此手机反馈的无震动不能直接归因为归零事件未触发；设备设置、通知类别策略和短脉冲触感仍可能有关，需要真机核对。

修正仍集中在原 `ReminderVibration`：计时归零使用 ALARM usage，Android 13+ 使用 VibrationAttributes，旧系统使用 AudioAttributes；不设置绕过系统策略的 flags。静音模式显式跳过，勿扰与系统振动强度继续由系统裁决。强度 0 不调用振动器，正强度使用 200—500ms 单次脉冲并调节振幅；无幅度控制硬件使用 DEFAULT_AMPLITUDE。默认强度 1 对应 500ms。

`CompletionReminder` 只在活动、未暂停、实际剩余时间等于零时消费一次结束事件。消费后即使强度为零、系统拒绝或用户继续停留在零也不重试；取消不会调用结束提醒，新会话重置门闩。以剩余毫秒判断，避免浮点进度舍入造成提前触发。

Logcat 标签 `FloatingFocus` 区分完成事件、已提交、强度零、静音、无振动器及 API 异常。`submitted` 仅代表请求已提交，不保证系统批准或真机产生触感；通知仍为静默的前台服务通知，不重复发出震动。

官方依据：[Vibrator](https://developer.android.com/reference/android/os/Vibrator)、[VibrationAttributes](https://developer.android.com/reference/android/os/VibrationAttributes)、[触摸区域 API](https://developer.android.com/reference/android/view/AttachedSurfaceControl#setTouchableRegion(android.graphics.Region))。

## 验收重点

检查设置实时生效和重启保留，三种形状在展开/归零/大尺寸下的文本、按钮与边界；检查实验室没有五项重复控制且重置不更改正式配置。前台和其他 App 上方各完成一次计时，检查系统振动记录；取消、零强度、持续零点不得产生额外请求。真机还需检查触感、静音/勿扰和厂商系统行为。

真机反馈（2026-10-23）：用户报告 REDMI K80 / Android 16 的系统闹钟振动正常，旧版 Floating Focus 归零和实验室手动触发均无触感，相关通知渠道开关已开启。当前没有该手机的系统振动拒绝日志，不能把模拟器执行成功视为 K80 修复完成。新版实验室手动按钮会显示提交或跳过原因，需覆盖安装后对照验证。

后续真机反馈（2026-10-23）：用户覆盖安装新版后确认「振动成功」。这确认该设备已恢复振动；用户未细分前后台、静音/勿扰等场景，因此不将这条反馈扩展为完整设备验收，也不据此断言旧版失效的唯一系统原因。

## 尺寸与预设的后续修正

连续变尺寸沿用原规则：前 50% 保持基础大小，后半程逐渐放大；节点模式在 50%、80%、100% 切换，最终为基础大小的 1.5 倍。变色方案不按时间放大。尺寸计算的修正不改变这些时间节点、强度和倍率。

## 浮窗位置与点击反馈

`OverlayPosition` 保留用户最后拖动的中心锚点，内容展开时仅临时限制在可见边界内，收起后按原锚点定位；在展开状态主动拖动则更新锚点。动态变尺寸、归零和加时也使用同一逻辑。时间区域移除默认矩形点击波纹，保留点击、语义和拖动，按钮仍有原有反馈。

加时从新一段 0% 进度开始，尺寸恢复用户基础值，50%—100% 再按现有连续变尺寸曲线放大；这不是重置用户尺寸设置。加时面板关闭后不保留展开布局，也不重建窗口或修改外观配置。
