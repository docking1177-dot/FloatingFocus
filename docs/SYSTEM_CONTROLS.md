# 控制中心、首页滑动与超时显示

## 控制中心快捷开关

设置首页的「控制中心快捷开关」请求系统确认添加「FF计时」。Android 13及以上使用官方添加确认；旧系统或未出现确认时，可从控制中心编辑页面手动添加。取消不创建计时，系统未确认不显示已添加。图标、底色和轮廓由系统处理。

| 当前状态 | 点击动作 |
|---|---|
| 空闲 | 使用「常用时长」的启动默认配置开始，不打开第三方App |
| 普通计时中 | 暂停 |
| 已暂停 | 继续同一会话 |
| 普通超时 | 打开FF首页，不直接结束 |
| C4归零前或超时 | 打开FF首页，不暂停、加时或直接结束 |
| 正在启动 | 暂不可点击 |

锁屏使用系统解锁流程，解锁后重新检查点击时的会话ID与加时段；旧请求不控制后来新建的会话。长按进入现有设置。打开首页采用`REORDER_TO_FRONT`，保留原设置/预设编辑页；返回可能回到原草稿，不清空返回栈。

`FocusTileService`只在系统监听期间收集现有会话、默认配置和启动门禁，没有独立时钟、轮询、后台保活或新的运行时权限。默认开始复用`WidgetStartActivity`，暂停/继续复用正式服务已有的带会话标识控制。磁贴不发结束动作。系统BIND权限声明用于保护磁贴组件，不向用户索要该权限。

官方依据：[Quick Settings](https://developer.android.com/develop/ui/views/quicksettings-tiles)、[Intent返回栈标志](https://developer.android.com/reference/android/content/Intent#FLAG_ACTIVITY_REORDER_TO_FRONT)。厂商控制中心的添加入口、分页、锁屏和显示样式仍需真机确认。

## 首页分页

「计时／预设／App」共用`HorizontalPager`状态，点击和左右滑动同步。顺序使用已有`HomeNavigationStore`；排序后仍按栏目ID保留当前页，滑动遵循新顺序。各页独立滚动，计时选择在页外共享。排序期间禁分页，分页期间禁排序，启动请求期间两者均禁用。详见[首页分栏](HOME_NAVIGATION.md)。

## 普通超时读数

普通倒计时到时后，浮窗同时显示当前段超时与本次计时累计。15分钟后超时5分钟，累计为20分钟；多次加时读取`Countdown.elapsedAt`，不再加超时或计划值。暂停沿用现有计时模型并冻结读数；历史记录原有的经过时间口径未修改，包含暂停的历史条目可能大于这个计时累计。它们都不是系统App前台使用时间。

到时仍自动展开一次，可以点击时间折叠/展开，两种状态都保留读数；原有加时、结束、形状、拖动与时间锚点继续共用原窗口。

开发者模式的「超时浮窗布局」比较三种候选：超时主显、累计主显、并列读数。Debug默认超时主显，独立存储在`debug_overtime_style`，立即影响真实普通超时浮窗。只读预览可切换形状、折叠/展开、长时长，不创建会话、浮窗、声音或记录，不改预设与正式外观。空间不足时并列读数自动换行，长时长显示时:分:秒。

Release暂采用双行的超时主显，不包含其他候选、选择器或实验偏好；正式最终样式仍待比较后确定。C4不读取这份选择。

## C4归零后的控制

C4将主题激活`c4Active`与口令限制`c4Locked`分开。归零前仍只有7355608正常解除；归零及之后可直接结束，不再校验口令。爆炸只触发一次，尾音之后进入持续`OVERTIME`，不恢复普通浮窗。

常态和完整装置都显示专属超时读数，可以展开、收起、拖动。完整装置的`#`位置改为「结束」，其他数字输入停用；归零前按住`#`再跨零松开不会变成结束。首页、通知与组件也可结束，主动结束立即停止剩余尾音。整个C4阶段及其超时均禁止暂停和加时，正式服务再次校验，不能只靠隐藏按钮。

时间轴、口令、整体主题和音量规则不变，音频仍仅本机Debug，Release无本地录音。详见[C4说明](C4_COUNTDOWN.md)。

## 检查与真机最小集

逻辑：`TimerTileModelTest`、`C4OvertimeControlsTest`、`OvertimeReadoutTest`、`StartAdmissionObservableTest`。

设备：统一`test-device.ps1`的`home_swipe`、`home`、`tile`、`overtime`、`overtime_preview`、`widgets`、`inline`和`preset_c4_extensions`。后两项分别验证普通加时与预设快照/C4禁加时边界；测试仅在专用模拟器执行并还原数据。

本轮实际结果、源码/APK身份及未执行范围见[验收记录](validation/20261102-controls-overtime.json)。三种布局截图来自本轮布局实现包；后续正式逻辑仅修正磁贴返回栈，Debug预览控件另修正大字号换行。不能把汇总通过或截图生成当作真机听感/触感通过。

真机只需优先补以下新差异，可与[统一真机清单](testing/REAL_DEVICE.md)同轮完成：

1. 用本轮同SHA的Debug，在HyperOS控制中心确认添加；空闲开始、暂停、继续，核对仍是一条会话。已有系统锁时从锁屏点击，未解锁前不执行，解锁后核对状态。模拟器不能替代厂商面板及真实安全锁。
2. C4自然归零后展开/收起和拖动，点完整装置的「结束」；首页/组件结束也应可用，不出现加时或暂停。逻辑和AOSP桌面已测，真机负责实际触摸及厂商入口。
3. 只有本地含录音Debug才试听爆炸尾音期间主动结束，确认剩余声音停止且无成功语音/双爆炸。Release或公开无录音包不以无声判故障。媒体音量、静音、勿扰保持日常系统规则，不为测试强制提高音量。

反馈用例ID、操作、实际现象及大致时间，按需附录屏/声音状态。可连接ADB时由AI提取日志，不要求手工筛日志。既有振动、权限、桌面快捷方式未被本次改动的部分不无理由全量重测。
